# 扩展中心与扩展生命周期

## 用途

扩展中心用于查看可访问的扩展包、了解其提供的场景模板和节点能力，并按扩展版本查看依赖、使用关系、版本与操作记录。扩展包的解析、环境准备、试运行、安装、个人启用和公开审核是不同状态；完成其中一步不代表后续步骤已完成。

扩展可以提供场景模板、计算节点、算法、数据类型或结果视图等声明。显示在扩展详情中的声明不代表它已安装、当前账号已启用或具备运行条件。扩展不等于任意代码插件：平台只在其受控生命周期和运行边界内处理包内容。

> 当前扩展中心体验分支尚未合并或部署。服务器仍运行 R2；本页描述的新目录交互及关系、版本、操作记录投影要等相应变更完成发布后才可在平台使用。已合并的扩展生命周期基线与该新界面/接口是不同状态。

## 前置条件与角色

- 查看扩展目录和详情需要 `workflow:read`。目录仅返回当前账号有权查看的内容；无权访问的私有包不会作为可见对象展示。
- 导入 schema 2 扩展需要 `workflow:read` 与 `workflow:edit`。ZIP 不超过 20 MiB，根目录应直接包含 `extension.json`。
- 包所有者可管理自己有权操作的扩展；管理员负责公开审核、安全撤销等管理动作。可执行操作由扩展状态、所有权和权限共同决定，详情页只显示当前可用动作。
- 公开审核通过的扩展仍需每个使用者为自己的账号单独启用。`workflow:read`、`workflow:edit`、`task:read` 等权限还会影响详情、操作和记录的可见范围。
- 旧 schema 1.0 包沿用兼容路径，不能据此假设它具备 schema 2.0 的独立个人启用、环境准备或试运行状态；标记为 `runtime_required` 的旧代码包仍不能安装或启用。schema 2.0 的受控代码能力不会自动扩展到旧包。

## 在扩展中心查找和了解扩展

1. 打开【扩展中心】。在目录范围中选择【全部扩展】【我的扩展】或【公共扩展】；管理员还可查看【待审核】。
2. 按名称或标识搜索，可切换【显示已归档】并使用分页浏览结果。目录搜索范围受当前所选范围和账号可见权限约束；公共目录不是不受限的公共市场。
3. 选择一个扩展卡片。详情中的【概览】按场景模板、可用节点和配套能力分组展示声明；选择卡片可查看声明信息。已启用的能力可从对应入口继续创建场景，或打开【算子中心】查看节点；节点在场景画布中组合使用。
4. 根据需要切换到【依赖与使用】查看可见的外部关系，或到【版本与操作记录】查看版本和有权限读取的扩展操作；【开发信息】提供精确版本、摘要、运行/验证报告和原始声明等技术信息。

### 关系图怎么读

关系视图可在图和列表之间切换。中心节点代表当前扩展版本；左侧是它依赖的外部能力，右侧是引用或使用该版本的记录。箭头方向为“被依赖方 → 使用方”。标记为缺失/无权、未就绪或已撤销的依赖，需要联系扩展所有者或管理员处理；图中不授予访问权限。

| 视图项 | 含义 |
| --- | --- |
| 外部依赖 | 当前版本依赖的精确能力版本；有权查看的包显示为扩展节点，平台内置能力显示为平台节点。 |
| 使用记录 | 当前账号有权查看的其他扩展依赖、已发布工作流版本、历史运行或历史场景实例引用。已删除工作流仅以历史版本引用显示，不提供已删除对象的打开入口。 |
| 包内引用 | 当前包自己的贡献之间的内部引用数量。只显示计数，不伪装成外部扩展关系。 |

投影只返回当前账号有权查看的关系。不可见或不存在的外部依赖以不可用项呈现，不会泄露私有包名称、依赖链或隐藏对象数量。反向工作流、运行及历史实例引用也按对象读取权限过滤，因此结果不是全平台审计清单。每侧关系可分页查看。

版本与操作记录按需读取并分页。操作记录需要 `task:read`；无该权限时页面会说明记录不可读。可见任务可打开任务详情查看结果或失败原因；已归档任务不会提供可打开的活动详情入口。此页记录的是扩展管理操作，不替代场景运行中心中的执行记录。

## 导入、准备、试运行、安装和个人启用

schema 2.0 包按以下顺序处理。每个动作可能返回异步任务；收到受理响应不等于动作已经成功。详情页显示任务状态，完成后应核对终态和扩展状态。

1. **导入并检查。** 有导入权限的用户展开【导入扩展】，选择 ZIP 并提交【上传并检查】。清单解析和安全检查由后台任务完成。上传后不会自动启用。
2. **准备环境。** 对需要受控代码运行环境的包，选择【准备环境】；平台检查可用的已批准运行环境和依赖配置。声明式包标为“无需代码环境”，不需要执行环境准备。
3. **试运行。** 对可执行包，环境就绪后按包中声明的试运行用例选择【试运行】，以验证声明的输入/输出约束。声明式包显示静态通过，这不是代码执行证据。缺少试运行用例或依赖、环境检查不通过时，平台会拒绝继续。
4. **安装。** 在依赖与冲突检查满足后，选择【安装】。安装登记精确版本的声明，不会自动安装或下载任意依赖。
5. **为当前账号启用。** 安装完成后，选择【为我启用】。公共扩展的每个使用者也必须单独启用；安装不等于任何账号已启用，公开也不等于已安装或已启用。
6. **使用已启用能力。** 从概览进入场景中心创建可继续配置的场景模板；在场景画布中组合可用节点。后续数据绑定、参数校验和运行仍受对应场景、数据和运行权限约束；查看扩展声明本身不会自动创建或运行场景。

管理员可能需要先审核公开申请。公开申请通过后，其他账号才能在有权查看的范围中发现该版本，但仍需分别启用。停用针对当前账号停止新的使用，不删除历史结果；安全撤销则会阻止此版本继续执行。归档是逻辑状态，不保证可以删除仍被引用的版本。

## 结果与失败处理

上传和管理操作可在详情页的最近任务区域查看进度及终态。切换目录筛选或刷新列表不会把“暂无扩展”当作加载错误。若列表、详情或关系/版本记录读取失败，可分别重试；上次选择的对象确认不可访问时，页面会清除失效选择并提示重新选择。短暂任务状态同步失败会自动重试或允许重新同步状态；重新同步只读取原任务，不会重复执行操作。

| 状态或问题 | 建议处理 |
| --- | --- |
| ZIP 无法解析或被拒绝 | 检查 ZIP 根目录是否直接包含 `extension.json`，修正清单或移除不支持内容后重新导入。错误码 `EXTENSION_INVALID_PACKAGE` 也可能表示清单结构无效，不只表示目录层级错误。 |
| 运行时尚未就绪 | 检查扩展声明的环境与状态；未批准的依赖不会由平台任意下载或安装。无法满足当前受控运行配置时，不要把静态解析通过当作可运行。 |
| 精确依赖缺失、无权或未就绪 | 在关系视图核对标识和版本；联系包所有者或管理员处理。平台不会绕过权限显示私有依赖。 |
| 安装、启用或审核失败 | 查看任务详情中的错误码和原因。确认权限、依赖及包状态后再重试；不要因为请求已受理就重复提交。 |
| 归档被引用保护阻止 | 查看可见使用关系并保留历史引用。归档不会强制删除历史工作流、运行结果或场景实例。 |
| 操作记录不可见 | 确认当前账号有 `task:read`。记录不可见不代表操作没有发生。 |

## 旧包兼容边界

历史 schema 1.0 包继续通过兼容逻辑显示与处理；它们没有 schema 2.0 的全部运行环境、试运行、公开审核及按账号启用语义。标记为 `runtime_required` 的 schema 1.0 代码包仍不能安装或启用；schema 2.0 提供的受控代码能力不会自动覆盖或升级旧包。旧包卡片可能只展示旧状态和管理员操作入口，旧算法包/历史记录仍可通过详情中的兼容入口查看。不要把旧包全局 `enabled` 状态解释成 schema 2.0 的个人启用状态，也不要把旧目录的兼容可见性当作新的公共发布流程。

平台不支持通过扩展包安装任意系统依赖、注入主站 DOM/JavaScript、注册任意路由或数据库迁移，也不提供任意依赖市场、通用 GPU 扩展运行环境或独立安全认证承诺。此边界仅描述扩展运行环境，不影响平台原有算法 GPU Worker 能力。支持范围以实际声明、精确依赖和当前批准运行环境为准。
