# 声明式扩展管理

## 用途

扩展管理用于登记可复用的算法、算子、工作流模板和场景模板声明。首批可安装扩展仅限声明式工作流/场景模板，并且只能引用平台中已安装的精确算法/算子版本。扩展不会把任意后端路由、数据库迁移或前端脚本变成插件。

含受支持算法/算子 Python 代码的包可以完成静态解析，但会标记为 `runtime_required`，本批不能安装或启用；代码环境准备和隔离执行属于后续独立工作包。夹带 hooks、路由、迁移、任意前端 JavaScript、远程 Schema `$ref` 或其他不受支持内容的包会被安全拒绝。

## 前置条件与角色

- 查看扩展和已启用模板需要现有 `workflow:read` 权限。
- 上传扩展需要现有 `algorithm:publish` 权限。
- 安装、启用、停用和归档仅限管理员/超级用户策略。
- 普通用户使用已启用模板创建自己的场景实例，按现有 `workflow:edit`、`workflow:run` 及数据文件读取权限完成绑定和运行。

具体权限以当前平台实际授权为准；无权限对象按不可见处理。

## 上传和解析

1. 选择 ZIP 扩展包上传。上传大小上限为 20 MiB。
2. 等待异步解析任务完成。系统保存原件并检查根清单、贡献类型、精确依赖、版本和安全边界。
3. 打开详情查看贡献、依赖问题、权限、运行能力和解析错误。内容预览不提供对象地址或内部路径。

扩展根清单使用 `extension.json` 1.0，包含扩展 ID、namespace、名称、版本、说明、作者、许可、平台版本、依赖和贡献。工作流节点必须声明精确 `node_code` 与 `node_version`；`builtin` namespace 为保留命名空间。

解析成功不等于已安装，已安装不等于已启用，已启用也不等于所有运行环境具备能力。任务中心是上传和解析任务的状态来源，关闭页面后可以重新打开任务查看结果。

## 安装、启用和停用

管理员在详情中确认依赖和冲突后执行安装。安装以包为单位原子注册：对象先保存，声明和贡献再事务激活；失败不留下半套可见资源。相同 ID、版本和摘要重复请求是幂等的；同 ID、版本但摘要不同会拒绝；不同版本可以并存。

声明式包安装后先处于已安装状态，管理员确认后才启用。缺少精确依赖或依赖版本不兼容时显示具体清单并阻止安装/启用，不自动下载依赖。含 `runtime_required` 的代码包不能安装。

停用阻止新的选择和运行，但不影响运行中的任务、历史结果或已有场景快照。归档是逻辑操作；仍被场景、工作流或历史记录引用的版本不能物理删除或垃圾回收。

安装、启用、停用和归档均返回异步操作任务。安装后的声明由 API 和 Worker 每次从数据库 catalog 读取，无需依赖服务重启。已提交运行使用自己的模板、算法和参数快照，不随之后停用或更新改写。

## 创建场景实例

普通用户从【已启用场景模板】选择模板，填写数据选择和参数。系统先校验参数 Schema、模板要求的绑定和数据权限，再执行适用性检查。创建成功后形成个人场景实例，保存模板声明快照和规范化数据选择。

运行实例时提供幂等请求标识。相同实例和请求标识重试会复用同一结果；不同标识创建新的工作流运行。运行沿用现有 workflow/task 状态和标准结果接口，当前首批只生成自动运行报告，不包含定时首版或人工确认版。

## 失败处理与安全边界

| 状态/问题 | 处理 |
| --- | --- |
| `rejected` | 查看静态解析错误；移除不支持内容后重新打包 |
| `runtime_required` | 本批不能安装；等待后续受控环境工作包，不把解析结果当作可运行 |
| 依赖缺失/冲突 | 安装精确依赖版本或更换扩展版本；平台不自动下载 |
| 安装事务失败 | 通过原任务重试，确认列表中没有半注册贡献 |
| 模板已停用 | 新运行被阻止；查看已有运行和历史结果不受影响 |
| 刷新/断网 | 从任务中心或扩展详情重新打开操作任务，配置和错误原因保留 |

扩展系统不执行上传的 Python、JavaScript、pip、hooks、迁移或路由；不允许远程 Schema 引用。解析、安装、启用、运行环境和工作流运行必须分别查看状态。
