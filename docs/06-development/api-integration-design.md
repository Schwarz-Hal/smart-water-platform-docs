# API Key 与系统集成设计

## 状态与范围

**这是设计提案与交互原型，不是已交付的 API Key 鉴权能力。**

本轮前端新增【API 与集成】入口（`/developer-center`）。页面可演示创建凭证、筛选、查看详情、停用、启用、撤销、接口分类切换和集成路径选择。数据是内存中的设计样例，离开页面后重置；`demo_` 前缀的示例标识不能用于鉴权，不写数据库或浏览器存储，不发起接口测试或连接外部系统。

现有登录令牌、权限和业务 API 均不改变。目录中的已有业务路径用于界面参考；`X-API-Key`、权限范围字符串、新增管理及智能体路径均是拟议接入约定，不能当作现有 v1 契约。请求模板中的域名与变量为占位内容，POST 请求还需按最终契约配置请求体。

截图要求中，本轮覆盖的是“API Key 与开发文档”和“接口集成方案”。数据增强资产建设、具体业务场景验证不是本轮新增实现，但作为后续集成的使用场景考虑。

## 页面组织

| 页签 | 内容 | 本轮交互 |
| --- | --- | --- |
| API Key | 应用、脱敏标识、权限范围、状态、有效期 | 本地创建、详情、筛选、停用/启用、确认撤销 |
| 接口目录 | 数据、模型、结果、智能体、管理 | 分类/接口选择，输入输出说明，cURL/Python 模板复制 |
| 集成方案 | 模拟预测软件、SCADA/RTU、水务智能体 | 切换方案，查看流程、输入输出和联调检查项 |

页面只保留一处【设计预览】状态标识。危险操作使用确认弹窗；新建凭证展示页在关闭后清除完整示例标识。展示的环境、调用日期和 Key 状态都是设计样例，不是生产遥测。

## API Key 后续功能

1. **身份归属**：凭证属于用户或服务应用。凭证权限取授权范围与所属主体实际资源权限的交集；不得以 Key 绕过数据集、模型、工作流版本的访问控制。
2. **生命周期**：创建、列表、详情、停用、启用、撤销、到期，以及后续轮换。正式 Key 使用安全随机值，完整值只返回一次；持久化不可逆摘要、前缀、所有者、范围和有效期，不保存明文。
3. **范围配置**：数据读取/上传、模型查看/执行、结果读取、批准的智能体工具调用、管理读取。正式权限码需映射平台权限体系，不直接复用原型中的字符串。
4. **运行约束**：可配置有效期、调用频率；按资源消耗区分上传和算法执行限额。首版不扩展团队组织、计费、市场或复杂审批。
5. **审计**：记录 Key ID、调用主体、时间、接口、状态和追踪标识，避免记录 Key 明文、敏感请求体或内部路径。页面显示最近使用时间和可筛选调用记录。
6. **权限变化**：主体注销、权限撤回或资源不可见时，凭证不能继续沿用旧授权。停用和撤销需要服务端生效，不能只更改界面状态。

拟议管理资源使用 `/api/v1/api-keys`，包含创建/查询及精确 Key 的更新与撤销。是否采用独立应用表、鉴权头名称和轮换宽限期，在后端实施时确认；本轮没有数据库迁移或已发布的新 API。

## 五类接口边界

| 类别 | 优先复用能力 | 待扩展内容 |
| --- | --- | --- |
| 数据 | 文件上传、不可变版本、SWNet 点位/时序与拓扑读取 | 外部系统批量监测上报、去重与接收回执 |
| 模型 | 模型版本查询、算法运行、训练生命周期 | 对外应用范围授权、调用配额与契约文档 |
| 结果 | 任务状态、结构化结果、文件产物 | 可选签名回调、投递状态及重试 |
| 智能体 | 已批准工作流和算法的执行能力 | 工具目录、参数 Schema、工具调用包装及证据引用 |
| 管理 | 现有用户、权限和审计基础 | Key 生命周期、按应用检索的脱敏调用记录 |

长任务复用既有任务标识与状态系统；MySQL 仍是状态依据，不另造一套集成任务状态。默认用查询任务后读取结果的闭环，回调是后续增量能力。输入与结果固定数据、算法、模型及工作流的精确版本。

## 三种接入路径

### 模拟预测软件

导入拓扑及点位映射 → 提交精确版本的分析输入 → 查询任务 → 将预测序列和异常事件返回业务软件。

联调核对坐标系、单位、采样间隔和时间范围；状态失败时给出可定位原因，重试不重复创建任务。这条路径不意味着已经实现校准水力仿真。

### SCADA / RTU

现场设备 → 协议网关 → 时间/单位/质量标记归一 → 数据接口 → 治理检测 → 告警业务系统。

OPC UA、MQTT 等协议经网关转换后进入平台；平台 HTTP API 不直接等同于 PLC/RTU 协议适配器。优先处理采集数据的读入、离线缓冲、重复记录与断点续传。现场控制指令不属于首版范围，另需设备权限及人工确认。

### 水务智能体

批准的工具目录 → 调用主体范围校验 → 精确版本分析任务 → 结构化结果与来源证据。

智能体只能调用批准的工具，不能获得无限制管理权限。参数校验、工具白名单、人工确认边界及审计复用平台能力；不在首版加入任意代码执行。

## 交付顺序与验收

| 阶段 | 交付 | 关键验收 |
| --- | --- | --- |
| 当前 | 页面与交互原型 | 页面可浏览、弹窗与状态操作连贯、无真实凭证或接口写入 |
| 第一阶段 | Key 存储与鉴权 | 有效 Key 可调用指定接口；越权/到期/撤销明确拒绝；日志无明文 |
| 第二阶段 | 核心业务 API 联调与文档 | 上传/选择数据 → 执行算法 → 查询任务 → 读取结果，完整可复现 |
| 第三阶段 | 外部系统适配 | 各选一个模拟软件、网关、智能体的最小接入案例 |

正式联调文档必须包含鉴权、版本、请求响应字段、错误码、分页、大文件和异步任务示例。后续是否交付签名回调、调用限额、IP 白名单和轮换窗口由具体对接约束决定，不在原型阶段宣称可用。

## 实现依据

前端原型代码位于 `src/app/features/developer-center/`，路由与导航采用既有统一策略。业务路径参考 Neo 的 `app/interfaces/http/data_files.py`、`algorithms.py`、`tasks.py` 及 v1 契约中结果接口；样例单独存于 `developer-center.data.ts`，没有调用凭证或集成后端的服务类。

## 高德天气存储（数据库层）

仅存储层，与 API Key 原型无关；未实现采集、调度或新 HTTP 接口，不保存 Key。三表共用前缀 `sw_amap_weather_`，后缀为 `response`、`live`、`forecast_daily`；去重键依次为 `request_id`、`adcode+report_time`、`adcode+report_time+forecast_date`。预报保留各发布批次。采集时间用 UTC；`report_time` 保留当地时间，`report_timezone=Asia/Shanghai` 是项目约定，接入时须确认。空值不补零，风力保留文本。字段依据[高德天气文档](https://lbs.amap.com/api/webservice/guide/api-advanced/weatherinfo)。
