# 扩展开发者入门与能力边界

## 扩展能做什么

扩展把可复用的算法、工作流节点、数据类型、结果可视化和模板资源交给平台登记，再由用户在有权限的范围内使用。当前清单支持 `algorithms`、`operators`、`types`、`visualizers`、`workflow_templates` 和 `scene_templates`。它们是资源种类，不等同于执行权限：例如，声明一个节点不会自动取得数据访问权，也不会让该节点对所有用户可用。

作者工具版本为 0.2.0，SDK 源码要求 Python 3.12；平台代码运行仍使用固定的 `python-cpu-v1` 配置。0.2.0 是工具版本，不代表运行 SDK 0.1.0、manifest schema 2.0 或执行协议 1.0 升级。独立包已在干净临时环境完成安装及作者 CLI 路径验证，QuickJS 浏览器视图和四档宽度也完成有限验收；临时合成账号下的预检页面走通真实后端预检，但没有完成正式上传和安装全链路。经授权的临时环境已对批准镜像完成六类容器检查；这些结果不代表生产部署或完整平台任务生命周期验收，详见[工具指南](./extension-author-tooling.md)。QuickJS 结果视图支持文本、指标、表格、图表、网络图和受限画布。视图脚本不能访问 DOM、网络或令牌。静态参数表单及资源版本选择控件可用；自定义节点界面和自定义参数 UI 尚未实现。资源种类可随平台协议扩展，未知种类应由平台拒绝，而不是自动执行。

一个扩展包可把几类资源组合起来：算法提供计算逻辑，节点把算法接入工作流，输出类型描述结果结构，结果视图呈现结果，场景模板则组合可复用流程。具体是否可用仍受各资源声明、包状态和用户权限约束。

| 能力 | 当前边界 |
| --- | --- |
| 算法与节点 | 通过 SDK 声明精确输入、输出、参数和入口；节点是否出现在当前用户目录中，仍取决于包状态、安装和个人启用等平台条件。 |
| 数据类型与引用 | 类型使用精确命名空间、编码和版本。可以声明跨层引用；引用不会授权读取或使用对应资源。 |
| 工作流／场景模板 | 可声明可复用模板。模板成员可引用其他层已声明资源，但扩展不能借此改写其他层的定义。 |
| 结果视图 | QuickJS 受限视图可呈现平台允许的结果块；不支持任意 HTML 或自定义页面代码。 |
| 运行与权限 | 安装时平台登记清单声明的贡献；运行时新结果和文件制品由平台登记、管理。扩展代码不能直接改写全局资源。私有执行与公开审核彼此独立，公开不授予数据访问权。 |

## 从样例开始

安装 Python SDK 后，可从算法项目开始；`init` 默认使用 `algorithm`，并提供 `node`、`type`、`visualizer`、`workflow`、`scene` 和 `timeseries` 七种用途模板。历史 `legacy` 模板仍保留：

以下命令在放置 `my-extension` 的父目录执行；输出 ZIP 使用新文件名，避免覆盖已有产物。

```console
swext init ./my-extension --namespace my-water --name example
swext check ./my-extension
swext inspect ./my-extension
swext build ./my-extension --output ./build/my-extension
swext pack ./build/my-extension ./example-1.0.0.zip
```

作者资源声明和实现源码分开维护；`build` 编译为现有 schema 2.0 manifest，算法可声明生成默认节点。`add` 用于加入资源文件，不覆盖已有源码。`check`、`inspect`、`diff` 默认提供简洁摘要，添加 `--json` 可输出结构化结果。`lock` 将精确依赖提供方快照绑定到源码摘要；外部依赖需要先从平台上传预检下载快照。上传前端会先执行只读预检，展示可见的资源、冲突和依赖信息，再由操作者确认上传；取消或预检失败不会自动提交 ZIP。私有且不可访问的依赖与缺失项保持同态。平台在后续解析和安装时仍会重新核验依赖和授权。

工具可分别运行明确标记为可信的本机测试，或指定不可变容器镜像测试；二者不能同时选择，容器不可用时不回退宿主。`verify-report` 只核对报告新鲜度，不授予授权。预览 cases 可切换输入，但不会自动重渲染。新导入组件的预检验证使用临时合成账号和内存目录；它没有验证正式扩展上传、安装或个人启用。本批未部署。完整命令及已完成验证边界见[扩展作者工具与独立开发包](./extension-author-tooling.md)。

本地 Python SDK 源码可从 Neo 项目的 `sdk/python` 安装；这与平台上传后使用的已批准运行镜像是两回事。SDK 源码安装不能代替平台环境准备或运行审批，开发包也不意味着任意依赖可安装。

## 资源版本与能力审批

扩展清单中的资源引用需要明确版本；已发布的扩展版本保持不可变，更新应发布新版本。数据输入应绑定具体资源版本，不能把“当前最新”当作可复现引用。包成员关系现由平台记录。作者项目可从单一资源声明编译清单，算法可生成默认节点；`diff` 给出保守结构差异，依赖锁记录精确提供方及源摘要。这些工具不会自动证明语义兼容或授权，平台仍须解析并复核。

普通贡献应限于扩展自身声明的算法、节点、类型、可视化或模板，并按平台支持的协议引用其他层资源。GPU 使用、网络连接器、新依赖、额外资源配额或更高级的隔离参数界面，若要开放，需平台另行批准和实现；这些不是作者在清单中自行申请即可获得的能力。认证、数据库迁移、路由、存储驱动、调度器及 Worker 宿主管理由平台维护者负责，不属于扩展包权限。

容器策略由平台控制，扩展清单不能自行选择镜像、挂载或主机能力。受限运行措施不等于对任意代码的安全认证，也不构成性能保证。有关上传、审核、安装、个人启用和执行阶段的详细约束，见[扩展生命周期与 Python SDK 首段](./extension-lifecycle-sdk.md)；面向使用者的操作见[扩展中心与扩展生命周期](../03-user-guide/extensions.md)。

## 遇到问题时

若 `check` 失败，先核对清单字段、入口路径、精确版本及包内文件；若静态检查通过但平台不显示节点或不能运行，再检查包状态、资源依赖、当前账号启用状态及批准运行环境。静态校验通过只说明声明符合工具检查，不代表上传、注册、授权或运行成功。不要通过本机可信执行绕过平台拒绝。

继续阅读[扩展作者工具与独立开发包](./extension-author-tooling.md)获取工具安装、预览与打包细节，再读[扩展生命周期与 Python SDK 首段](./extension-lifecycle-sdk.md)了解平台状态和运行边界。若需要新的资源种类或宿主能力，应先由平台维护者实现并批准相应协议，不要在扩展中假设未支持的行为。
